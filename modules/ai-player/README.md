# Experimental AI Players

Temporary, disposable test opponents. **This implementation is expected to be completely removed**, not maintained as a permanent compatibility layer. Remote players and provider infrastructure remain separate future work.

## Select scripts and share the author kit

Administration → select an AI-enabled game → AI Player panel. Choose an AI-controlled nation and an **AI script**, then **Change AI script**. Assignment of a manual nation also accepts the selected script. Each nation can use a different script. Existing assignments default to Experimental V1; switching preserves orders/readiness and takes effect at the next uncommitted decision. The existing ten-controller limit remains.

Install trusted single-file PHP scripts in `modules/ai-player/scripts/` and refresh Administration. Filenames are stable identifiers (`continental-defender.php`); `@ai-name` supplies the label. No registration or engine edit is needed. Per-script notebooks persist separately across switches; releasing the controller deletes all its notebooks.

**Download AI author kit (.zip)** provides the skill, contract, starter, current V1, synthetic snapshots and standalone PHP runner with the real production forecast. **Download player snapshot** exports the chosen nation's current private information and selected notebook: share deliberately. The kit alone contains no live data. The local artifact can be rebuilt with `php8.3 modules/ai-player/build-kit.php`. See [author instructions](author-kit/novus-ai-author/README.md) and [contract](author-kit/novus-ai-author/references/api.md).

Scripts return plans; the game applies them with ordinary player validation. A failed/invalid custom plan gets one V1 fallback after full rollback, without changing the selected script. If V1 also fails, AI play pauses. Stale control/turn contexts are not policy failures. Preview validates structure and is free of game writes, but does not prove legality; a future script can still incur provider costs during preview.

Decisions run in a PHP child process with a 20-second deadline and 256 MiB memory limit, not a security sandbox. Only install trusted code. `config/ai-player.php` contains the local runner settings. No LLM integration is bundled. Deployment requires the additive `2026_09_23_000000_add_ai_script_selection.php` migration; it adds the script identifier only, without advancing games.

## Try it

In Administration, start a classic or saved-map game and select 0–10 AI players. The standalone generated-map start supports the same options. The watch-test preset selects six mixed personalities plus protection for human nations. A connected five-territory human homeland is left unclaimed at creation; this is not permanent protection for neutral land.

Join normally, then open **Auto-ready** beside Ready. Enable it and select a delay (default ten seconds). Bots submit normal plans and become ready one at a time; once all humans and bots are ready, normal resolution opens the next turn. Auto-ready only presses Ready for your nation; it does not run its economy/army. Map inspection remains available, and News opens the turn report without automatic briefing popups interrupting watching.

Bot work has separate client command state (`experimental-ai/AICommands.js`): it does not flash or disable your Ready/orders controls. You can submit while a bot is thinking. Shared confirmed reads reconcile afterward without interrupting your own submission; actual turn processing, stale data and your own pending/uncertain command still gate actions. A failed/unknown bot result stops the driver, not the human command lane. Manual commands during bot work still pause Auto-ready. Server locks and validation are unchanged.

Pause stops future automatic Ready submissions, not an accepted action. Manual commands and unsent drafts pause Auto-ready. Closing/reloading the page turns Auto-ready off and stops that browser's AI driver; another open participating client may continue driving bots. Server failure/pause stops future AI work until explicit recovery. Ordinary turn expiry remains enabled but cannot skip unready/paused AI participants. Human protection blocks automated attacks on human-owned land, including ownership changing during the shuffled battle phase; ordinary defense against human attacks is unchanged.

Administration offers private explanations, preview (no gameplay writes), one AI step, a bounded batch for the remaining AI players in the current turn, stop, pause/resume, explicit release to manual control and reassignment of any manual nation to a fresh AI controller. Release preserves the nation/account/orders/history and returns it to Planning; use existing admin account impersonation after release. Reassignment preserves current orders/readiness, starts with fresh AI memory and supports cautious/balanced/aggressive profiles, up to 10 AI nations. Multi-turn console runner:

```sh
php8.3 artisan app:ai-play GAME_ID --preview
php8.3 artisan app:ai-play GAME_ID --turns=10
```

The console runner requires an explicit active game, caps batches at 100 turns, and never readies humans. Use it only on games you intend to advance. `AI_PLAYER_ENABLED=false` stops the experiment; existing AI-controlled games require deliberate recovery/handover. Zero-bot games continue normally. Setup controls remain visible when disabled, but the server rejects nonzero bot creation.

## Boundary and behavior

- `scripts/experimental-v1.php`: the complete current strategy, plain arrays in/out and a supplied read-only forecast. No Laravel, model, database or HTTP imports. Regional objectives, Food/Capital/Ore choices, Infantry/Artillery recruitment, group attacks, escalation and defensive reserves. No diplomacy/aircraft/armor or omniscient opponent reads. `V1Experimental.php` is a small compatibility wrapper for existing policy tests; other scripts can use all five current unit types.
- `Runner.php`: one AI decision per request; thinks outside game locks, rechecks context under shared game locks, and atomically applies commands/memory/Ready/completion. Duplicate requests cannot select the next bot. Custom failures get one V1 fallback; failure of V1 leaves the nation unready, rolls back commands, pauses AI play and records an admin-visible result. Lock contention is a conflict, not a failed strategy. Rollback rotates generation and restores completed plans' readiness and notebooks rather than replaying their orders.
- `Setup.php`: ordinary accounts/nation creation, legal connected homes, no extra stocks/population/units. Undisclosed random passwords; no admin privileges.
- `app/Integrations/AIPlayers/GameAdapter.php`: only bridge to authoritative player observations, game-owned allocation/forecasting and shared commands. Public approximate army sizes inform enemy garrison estimates. Recent defensive battle locations come from the nation's own participation.
- Three module-owned tables hold game settings, nation assignments and per-turn reports. Their foreign keys point to game records: deleting an assignment cannot delete a nation.

Balanced/aggressive neutral opening uses at least five Artillery + two Infantry (180 power); cautious requires 300 power. Repulses raise requirements. The first successful conquest is not guaranteed: combat remains random. Aggressive bots prioritize a neutral foothold initially, then nation war becomes more attractive with turn/territory growth. Defenders are estimated, so attacks and defenses can be poor. Economic forecasts freeze production/population over three upkeep turns rather than assuming future conquest will pay for an army; plans are recalculated each turn. Food reserve target is three turns. Recruitment and recurring Capital sustainability are checked separately.

### V1.1 regional strategy and conflicts

The turn-number war escalation was removed after a running game reached turn 439 with coherent economies but scattered strategic behavior. The policy now identifies land components from authoritative land-only connections, remembers a home landmass, and uses a stable seed-derived land-focus value. Existing games initialize the home as the component containing the largest part of the nation's current territory; new games naturally retain their connected starting homeland. Local neutral land is normally the strongest target. For balanced nations, a strong land focus or active conflict can sometimes make completing the home landmass more important than an overseas neutral.

Cautious nations use a regional doctrine: they pursue local neutrals and rivals, then may remain satisfied and defensive once the home landmass is controlled. Balanced seeds produce continental or frontier behavior. Aggressive nations use a conqueror doctrine and may initiate wider wars, while still valuing local neutral growth. Human protection always overrides personality.

The adapter exposes only the nation's own recent nation battles. V1 keeps bounded per-opponent conflict memory with hostility, last turn, battles and attacks received. Attacks received and losses weigh most; hostility decays every quiet turn and old zero-score entries disappear. Active conflicts influence target choice without revealing enemy orders or unrelated battles. The battle-ID fence prevents the same event being counted on every decision. This state uses the existing JSON memory, so no migration or game restart is required. Already committed orders are not rewritten; each bot adopts the policy on its next uncommitted turn.

V1.2 lets sufficiently hostile conflicts sometimes escalate across two or three territories. A repeatable seed/turn roll makes escalation variable without making retries nondeterministic. Every front must independently have at least five Artillery, two Infantry and its estimated required power; otherwise the bot opens fewer fronts or continues mustering. Conflict campaigns also hold two to four Infantry out of the assault and move them toward the contested frontier in expectation of retaliation. This can deliberately create escalation cycles; it remains experimental policy rather than a combat-rule change.

## Verification and limits

All gameplay verification used a dedicated temporary MariaDB socket/database and public root; no live game was created, populated, advanced or rolled back. The additive AI migration was installed in the workspace database and client assets rebuilt.

- Pure policy checks: baseline grouped attack, deterministic choices for fixed inputs, personality, reinforced retry, defense, later enemy targeting and elimination.
- V1.1 pure-policy checks add local-neutral priority, land-only components, seeded continental-versus-frontier choice, satisfied cautious powers, aggressive wider war, retaliation and conflict decay/no double counting. A read-only preview against the active turn-439 game loaded all seven observations: five redirected to local neutral growth, two retained active conflicts, with no command, memory or readiness write.
- Isolated real allocator/forecast parity for four competing/cutoff/reserve plans; ownership and protection including a neutral becoming human-owned in the resolution turn; failure injected after commands and Ready; duplicate/generation/rollback checks; assignment deletion preserves nation; provisioning failure preserves prior game/accounts; disabled module permits ordinary zero-bot games.
- Two independent PHP processes using shared isolated file locks committed exactly one AI turn. Preview and repeated step did not add orders/deployments.
- Six-bot classic calibration reached turn 63: 40 neutral battles, 9 nation battles, neutral expansion and defensive reactions. First baseline attacks occurred on turn 24 and conquest was visible on turn 25. Some aggressive nations in the initial tuning waited too long for enemy attacks; the policy was adjusted to seek an initial neutral foothold. This mixed-version calibration is evidence of mechanics/loop behavior, not a reproducible benchmark.
- Ten bots provisioned on a real generated map and completed three turns; creation preserved initial human starting space. Those turns took approximately 14–17 seconds including normal resolution in this isolated environment. Six-bot turn time varied roughly 5–23 seconds as armies grew. These are not load-test guarantees.
- The compact two-bot fixture reached ordinary victory at turn 48. The initial run exposed an Ore-affordability bug on turn 43, rolled back/paused correctly, then was explicitly resumed after the fix; turns 43–48 completed automatically. This was not an uninterrupted from-start run of the final policy. A pure-policy and actual-engine regression now forbid spending resources that would only become available after deployment expenses cause reallocation.
- Node/service checks, generated PHP contracts and focused Chromium journeys passed: sequential visible bot readiness, Ready/next-turn watching, persistent canvas, mobile/French controls and ordinary HUD/deploy/move/briefing regression. A real isolated PHP/HTTP journey checked authentication/CSRF, archived AI reports, setup preset/cancel and the legacy-shaped manual-command guard. A live two-tab browser check verifies one Auto-ready countdown owner and release on tab closure.

Re-run scripts under `tests/client/ai-*` only with the explicitly isolated test bootstrap. The compact-map fixture is a legal 20-land-region generated-map geometry with ordinary rules/starts for checking victory; it is not a production generator preset.

Remaining limits: one-front tactical heuristics, static short-horizon economic assumptions, imperfect enemy estimates, no background daemon, no API provider, no universal victory guarantee or poor-map viability guarantee. Protection can prevent a legal victory if humans hold indispensable land. The ten-bot check is a startup/turn smoke test, not a long-game balance claim. Web Locks require browser support/secure context; without them, server bot idempotency still applies, but users should keep Auto-ready in one tab. No concurrent multi-user browser load benchmark was performed.
